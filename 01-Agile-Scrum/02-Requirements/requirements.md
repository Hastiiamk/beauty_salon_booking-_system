# جلسه دوم – مهندسی و استخراج نیازمندی‌ها
## پروژه: سیستم رزرو سالن زیبایی (Beauty Salon Booking System)

### ۱. مقدمه

مهندسی نیازمندی‌ها یکی از مراحل مهم در توسعه نرم‌افزار است. در این مرحله نیازها و انتظارات کاربران و سایر افراد مرتبط با سیستم شناسایی و بررسی می‌شوند.

هدف این پروژه طراحی یک سیستم رزرو آنلاین برای سالن زیبایی است که مشتریان بتوانند خدمات سالن را مشاهده کنند، آرایشگر موردنظر خود را انتخاب کنند و به‌صورت آنلاین نوبت رزرو کنند.

در این مرحله ذینفعان سیستم و نیازمندی‌های عملکردی و غیرعملکردی آن شناسایی می‌شوند.

### ۲. شناسایی ذینفعان (Stakeholders)

ذینفعان افرادی هستند که از سیستم استفاده می‌کنند یا به نحوی بر عملکرد آن تأثیر می‌گذارند.

ذینفعان اصلی سیستم عبارت‌اند از:

| شناسه | ذینفع | نقش و مسئولیت |
|---|---|---|
| S-01 | مشتری | مشاهده خدمات، انتخاب آرایشگر و رزرو نوبت |
| S-02 | مدیر سالن | مدیریت خدمات، قیمت‌ها و نوبت‌ها |
| S-03 | آرایشگر | مشاهده برنامه کاری و نوبت‌های خود |
| S-04 | مسئول پذیرش | ثبت و پیگیری نوبت‌های مشتریان |
| S-05 | مدیر سیستم | مدیریت کاربران و کنترل دسترسی‌ها |

### ۳. نیازمندی‌های عملکردی (Functional Requirements)

نیازمندی‌های عملکردی مشخص می‌کنند که سیستم چه وظایفی باید انجام دهد.

| شناسه | شرح نیازمندی |
|---|---|
| FR-01 | سیستم باید امکان ثبت‌نام مشتری را فراهم کند. |
| FR-02 | سیستم باید امکان ورود کاربران را فراهم کند. |
| FR-03 | سیستم باید فهرست خدمات و قیمت‌ها را نمایش دهد. |
| FR-04 | سیستم باید فهرست آرایشگران را نمایش دهد. |
| FR-05 | سیستم باید زمان‌های خالی آرایشگران را نمایش دهد. |
| FR-06 | سیستم باید امکان رزرو آنلاین نوبت را فراهم کند. |
| FR-07 | سیستم باید از رزرو هم‌زمان یک زمان توسط چند مشتری جلوگیری کند. |
| FR-08 | سیستم باید امکان مشاهده و لغو نوبت را فراهم کند. |
| FR-09 | سیستم باید به مدیر اجازه مدیریت خدمات و قیمت‌ها را بدهد. |
| FR-10 | سیستم باید به آرایشگر اجازه مشاهده برنامه کاری خود را بدهد. |
| FR-11 | سیستم باید به مدیر امکان مشاهده و مدیریت تمام نوبت‌ها را بدهد. |

### ۴. نیازمندی‌های غیرعملکردی (Non-Functional Requirements)

نیازمندی‌های غیرعملکردی ویژگی‌های کیفی و محدودیت‌های عملکرد سیستم را مشخص می‌کنند.

| شناسه | شرح نیازمندی |
|---|---|
| NFR-01 | رابط کاربری سیستم باید ساده و قابل فهم باشد. |
| NFR-02 | سیستم باید از اطلاعات شخصی کاربران محافظت کند. |
| NFR-03 | صفحات اصلی سیستم باید در شرایط عادی حداکثر طی ۳ ثانیه بارگذاری شوند. |
| NFR-04 | سیستم باید در تمام ساعات شبانه‌روز در دسترس باشد، به‌جز زمان‌های تعمیر و نگهداری برنامه‌ریزی‌شده. |
| NFR-05 | سیستم باید در مرورگرهای رایج مانند Chrome و Firefox قابل استفاده باشد. |
| NFR-06 | سیستم باید از ثبت نوبت‌های تکراری برای یک آرایشگر در یک زمان جلوگیری کند. |
| NFR-07 | اطلاعات نوبت‌ها باید به‌صورت منظم پشتیبان‌گیری شوند. |

### ۵. ارتباط ذینفعان با نیازمندی‌ها

هر یک از ذینفعان انتظارات متفاوتی از سیستم دارند:

- مشتری به مشاهده خدمات، قیمت‌ها و رزرو آسان نوبت نیاز دارد.
- مدیر سالن به مدیریت خدمات، قیمت‌ها و تمام نوبت‌ها نیاز دارد.
- آرایشگر به مشاهده برنامه کاری و نوبت‌های خود نیاز دارد.
- مسئول پذیرش به ثبت و پیگیری نوبت‌های مشتریان نیاز دارد.
- مدیر سیستم به مدیریت کاربران و کنترل دسترسی‌ها نیاز دارد.

### ۶. نتیجه‌گیری

در این جلسه ذینفعان اصلی سیستم رزرو سالن زیبایی شناسایی شدند و نیازمندی‌های عملکردی و غیرعملکردی سیستم استخراج شدند.

این نیازمندی‌ها مبنای مراحل بعدی پروژه، به‌ویژه مدل‌سازی UML و طراحی نرم‌افزار خواهند بود.
